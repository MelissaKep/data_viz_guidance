# Tables 
Also known as:
Data Tables, Reference Tables, Summary Tables

Tables are structured, row‑and‑column displays used to present numerical information with precision and clarity. They excel at organizing detailed values, supporting exact look‑ups, and enabling comparisons across many categories or time periods. A well‑designed table highlights patterns without requiring interpretation of shapes or positions, making it a foundational tool in analytical reporting.

Tables are especially well‑suited when:

* Users need precise numerical values rather than estimates drawn visually.
* The data contain many categories, detailed subgroups, or multiple levels of classification.
* The goal is to report all data transparently, even when patterns are not easily visualized.
* Users require complete values (e.g., standard errors or confidence intervals).
* The table acts as the authoritative source for downstream use (e.g., CSV, Excel)

Much of the guidance for table construction—including formatting, ordering, indentation, labeling, and accessibility—comes from the U.S. Census Bureau’s Editorial Reference Guide Table Guidelines section.

## Best Practices 

### Essential 

* Present data with minimal visual clutter in a clean, structured format.
* Order rows and columns in a meaningful sequence—alphabetical, chronological, geographic, or by importance.
* Include clear notes, footnotes, and sources to document definitions, statistical caveats, or data exclusions.
* Use consistent rounding and decimal precision within the same table.
* Standardize symbols: When using Census Bureau data, use the standard symbols below. Otherwise, use consistent symbols and define them in the table note. Do not use additional punctuation (such as parentheses) with symbols.

| Standard Symbol	|  |
| :---------------: | ----------------- |
| X	| Not applicable. |
| N	| Not available.  |
| B	| Base too small to meet statistical standards for reliability of derived figure |
| D	| Data withheld to avoid disclosure. |
| S	| The estimate is withheld because estimate did not meet publication standards. |
| Z	| Represents or rounds to zero. |
|  | All letters above, except X and N, may have a variation of the standards description if needed to clarify the statistics.  For example: Z entry if less than half of a unit of measurement from zero and there is a meaningful difference between an actual zero and a rounded zero for the particular statistics. |
|  | Estimates that truly equal zero should be shown as numeric values (for example, 0.00 for two‑decimal precision). Use the symbol Z only when an estimate is less than half a unit from zero and it is important to distinguish a rounded zero from an actual zero. |
| \*	| Denotes statistical significance |
| ±	| Denotes margin of error |

### Avoid

* Overly complex layouts, including nested spanners or too many hierarchical row levels.
* Inconsistent formatting, such as mixing fractions, percentages, and symbols haphazardly.
* Structural misalignment across reports: Avoid switching formats between similar tables; apply a unified structure across them. (Note: Moved here from your original draft's "Avoid" section typo).

## Additional Recommendations 

### Recommended 

* Use tables when precision matters. Tables are ideal when exact values must be available for comparison, citation, or additional analysis.

### Not recommended 

* Splitting related categories across multiple tables when a single combined table would better support comparison.
* Combining too many metrics in one table without clear grouping or spanners.
